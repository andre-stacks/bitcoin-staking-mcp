# Bitcoin Staking MCP — Implementation Audit

Audit date: August 6, 2026. Scope: the hackathon plan, repository implementation, offline tests, live PoX endpoints, and host behavior. This is an engineering acceptance record, not a protocol security audit.

## Verdict

The read-only MCP core and concierge reference workflow meet the hackathon MVP's material product and implementation requirements. The audit closed five correctness gaps: demo-derived yield lost its demo label, manifest-backed testnet reads could route to mainnet, compatibility claims could cite nonexistent source IDs, a valid zero-rate scenario was treated as missing data, and abstention behavior was not explicit enough across every host instruction surface.

The server now fails closed for missing evidence and live-read errors. The prompt, skill, and response-standard resource all require the fixed abstention “This MCP does not currently verify that.” This materially reduces unsupported answers, but it is not a mathematical guarantee over prose generated by an arbitrary host model. The enforceable boundary is the deterministic tool output: schemas, evidence statuses, source URLs, assumptions, error states, and read-only capabilities.

## Anti-hallucination controls

1. Facts may come only from current MCP outputs and resources.
2. Every successful result carries `dataStatus`, sources, assumptions, and `verifiedAt`.
3. Missing evidence produces an explicit abstention and names the required evidence.
4. Unknown, not-verified, not-assessable, context-only, and empty results are terminal states.
5. Live failure returns a typed retryable error and cannot fall back to demo data.
6. Demo terms remain demo after deterministic derivation.
7. Wallet, protocol, SDK, application, custodian, and audit claims remain separate evidence layers.
8. Tool contract tests prohibit transaction-payload fields and invoke every registered tool offline.

## Institutional voice acceptance

The intended voice is an institutional Bitcoin Staking diligence analyst: neutral, calm, concise, factual, non-promotional, and decision-first. CFO and investment questions prioritize availability, custody, liquidity, economics, material risk, and the next diligence item. Technical and security questions prioritize mechanisms, ownership boundaries, deterministic verification, gaps, and pinned primary sources. The response avoids unsupported assurances such as “safe,” “guaranteed,” “trustless,” or “risk-free.”

## Verification record

- `npm run check`: passed. The offline runner discovered 38 tests; 36 passed and the two opt-in network tests were skipped as designed. Type-checking and the production build passed.
- `npm run test:live`: passed against the current mainnet PoX API.
- `npm run test:testnet`: passed against the dedicated PoX-5 testnet API.
- `npm run demo:proof`: passed. At `2026-08-06T18:44:07Z`, the endpoint reported PoX-5 scheduled at burn height `2702`, current burn height `2663`, and no assessable configured PoX-5 bond. This is a time-specific observation, not a permanent network fact.
- Official skill quick validation: passed.
- `npm audit --audit-level=high`: reported zero known vulnerabilities for the locked dependency graph at audit time.
- Package dry run: passed and includes the compiled server, demo manifest, README, and concierge skill.
- Isolated installer acceptance: passed against the real Codex and Claude CLIs using a temporary home. Setup, handshake, registration reads, global-skill discovery, check, and uninstall all completed without changing the user's normal host configuration.
- Codex stdio health and adversarial host turn: passed. The model rejected an instruction to assume Leather safety, used the fixed abstention, and identified the missing release-specific proof.
- Claude stdio health: passed. The model-turn acceptance test could not run because the local Claude OAuth access token returned `401 OAuth access token has been revoked`; this remains external and must be rerun after reauthentication.

## Residual gaps that must remain explicit

- Public links to final audit reports, precise in-scope commits, findings, and remediation attestations are not currently included.
- Leather, another wallet, or a custodian requires release-specific end-to-end proof for the exact application flow; protocol or SDK compatibility is insufficient.
- A configured testnet bond is not a mainnet opportunity and is not investable.
- A target rate is not a promised or realized return; reward-pool constraints and implementation terms still apply.
- Final Claude/Codex host acceptance depends on valid local host authentication and the exact installed host versions.
- The primary demo recording, editing, upload, and submission form are manual delivery tasks.
